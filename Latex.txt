% Abstract
\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}

This project presents a comprehensive implementation of a facial expression recognition system using deep learning and containerization technologies. The system classifies facial expressions into seven emotion categories (angry, disgust, fear, happy, sad, surprise, neutral) using a custom Convolutional Neural Network (CNN) trained on the FER-2013 dataset. The entire machine learning pipeline, from data preprocessing to model deployment, is containerized using Docker, ensuring reproducibility and portability across different computing environments.

The final model achieves a test accuracy of 61.77\% after 40 epochs of training, with particular strength in recognizing happy (86.4\% recall) and surprise (74.9\% recall) expressions. The project demonstrates modern MLOps practices including containerized training, RESTful API deployment, version control, and automated workflows. Training was performed on CPU-only hardware (Intel i5-1145G7, 16GB RAM) with a total training time of 1.1 hours, processing 918,720 images at an average speed of 231 images per second.

\textbf{Keywords:} Facial Expression Recognition, Deep Learning, CNN, Docker, MLOps, FER-2013, Emotion Classification

% Introduction
\section{Introduction}

\subsection{Context and Motivation}

Facial expression recognition is a fundamental aspect of human-computer interaction and affective computing. The ability to automatically recognize and interpret human emotions from facial expressions has wide-ranging applications in various domains including healthcare (patient emotion monitoring), education (student engagement tracking), security (threat detection), customer service (satisfaction analysis), and human-robot interaction.

Recent advances in deep learning have significantly improved the accuracy of facial expression recognition systems. Convolutional Neural Networks (CNNs) have demonstrated exceptional performance in computer vision tasks, making them the architecture of choice for emotion classification from facial images.

\subsection{Project Objectives}

The primary objectives of this project are:

\begin{itemize}[itemsep=0.3em]
    \item Design and implement a CNN-based facial expression recognition system
    \item Train the model on the FER-2013 dataset to classify seven emotion categories
    \item Containerize the entire machine learning pipeline using Docker
    \item Deploy the trained model as a RESTful API for real-time inference
    \item Achieve reproducible results across different computing environments
    \item Document the complete development and deployment workflow
    \item Implement modern MLOps practices for model versioning and deployment
\end{itemize}

\subsection{Dataset: FER-2013}

The Facial Expression Recognition 2013 (FER-2013) dataset is a widely-used benchmark dataset for emotion recognition research. It was introduced as part of a Kaggle competition and has become a standard evaluation dataset in the field.

\textbf{Dataset Characteristics:}
\begin{itemize}[itemsep=0.3em]
    \item \textbf{Total Images:} 35,887 grayscale facial images
    \item \textbf{Image Size:} 48×48 pixels
    \item \textbf{Classes:} 7 emotion categories (angry, disgust, fear, happy, sad, surprise, neutral)
    \item \textbf{Split:} Training (22,968), Validation (5,741), Test (7,178)
    \item \textbf{Source:} Automatically collected from the internet using Google image search
\end{itemize}

\subsection{Technical Stack}

The project leverages the following technologies:

\begin{itemize}[itemsep=0.3em]
    \item \textbf{Deep Learning:} PyTorch 2.0.1 (CPU version)
    \item \textbf{Containerization:} Docker and Docker Compose
    \item \textbf{API Framework:} Flask for RESTful API deployment
    \item \textbf{Data Processing:} NumPy, Pillow, torchvision
    \item \textbf{Visualization:} Matplotlib, seaborn, scikit-learn
    \item \textbf{Development Environment:} Python 3.9, Ubuntu 22.04 (Docker base)
\end{itemize}

\subsection{Design Rationale}

\begin{itemize}[itemsep=0.3em]
    \item \textbf{Progressive Filter Increase:} Filters increase from 64 → 128 → 256, allowing the network to learn increasingly complex features
    \item \textbf{Batch Normalization:} Applied after each convolutional and FC layer to stabilize training and accelerate convergence
    \item \textbf{Dropout Regularization:} 25\% dropout after conv blocks and 50\% after FC layers to prevent overfitting
    \item \textbf{ReLU Activation:} Used throughout for non-linearity and gradient flow
    \item \textbf{MaxPooling:} Reduces spatial dimensions by 2× at each block, creating a hierarchical feature representation
\end{itemize}

    \item \textbf{Compression:} No compression applied; potential for 4× reduction with float16 quantization
\end{itemize}

\subsection{Optimization Strategy}

\subsubsection{Learning Rate Scheduling}

We employed a ReduceLROnPlateau scheduler that monitors validation loss and reduces the learning rate when no improvement is observed:

\begin{lstlisting}[language=Python, caption={Learning Rate Scheduler Configuration}]
scheduler = ReduceLROnPlateau(
    optimizer,
    mode='min',
    patience=2,      # Wait 2 epochs before reduction
    factor=0.3,      # Multiply LR by 0.3
    verbose=True
)
\end{lstlisting}

This adaptive learning rate strategy allows the model to make large updates early in training and fine-tune parameters later with smaller steps.

\subsubsection{Early Stopping}

Early stopping with patience=7 prevents overfitting by monitoring validation loss:

\begin{lstlisting}[language=Python, caption={Early Stopping Implementation}]
class EarlyStopping:
    def __init__(self, patience=7, min_delta=0):
        self.patience = patience
        self.min_delta = min_delta
        self.counter = 0
        self.best_loss = None
        
    def __call__(self, val_loss):
        if self.best_loss is None:
            self.best_loss = val_loss
        elif val_loss > self.best_loss - self.min_delta:
            self.counter += 1
            if self.counter >= self.patience:
                return True  # Stop training
        else:
            self.best_loss = val_loss
            self.counter = 0
        return False
\end{lstlisting}

\section{Docker and MLOps Implementation}

\subsection{Containerization Strategy}

Docker containerization was central to this project, enabling reproducible machine learning workflows across different environments. The implementation follows industry best practices for ML containerization.

\subsection{Docker Architecture}

The project employs a multi-service Docker architecture defined in \texttt{docker-compose.yml}:

\begin{lstlisting}[language=bash, caption={Docker Compose Configuration}]
version: '3.8'

services:
  training:
    build:
      context: .
      dockerfile: Dockerfile
    image: facial-expression-recognition-training:latest
    container_name: emotion-training
    volumes:
      - ./data:/app/data
      - ./models:/app/models
      - ./results:/app/results
    command: python src/train.py
    
  api:
    build:
      context: .
      dockerfile: Dockerfile
    image: facial-expression-recognition-api:latest
    container_name: emotion-api
    ports:
      - "5000:5000"
    volumes:
      - ./models:/app/models
    command: python api.py
\end{lstlisting}

\subsection{Dockerfile Design}

The Dockerfile is optimized for CPU-based PyTorch training and inference:

\begin{lstlisting}[language=Docker, caption={Dockerfile for Training and Inference}, label={lst:dockerfile}]
FROM python:3.9-slim

# Install system dependencies
RUN apt-get update && apt-get install -y \
    libgl1 \
    libglib2.0-0 \
    && rm -rf /var/lib/apt/lists/*

# Set working directory
WORKDIR /app

# Copy requirements and install Python dependencies
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY src/ ./src/
COPY api.py .
COPY data/ ./data/

# Expose API port
EXPOSE 5000

# Default command (overridden by docker-compose)
CMD ["python", "src/train.py"]
\end{lstlisting}

\subsubsection{Dockerfile Optimization Techniques}

\begin{itemize}[itemsep=0.3em]
    \item \textbf{Multi-stage Build:} Not used (single-stage sufficient for this project)
    \item \textbf{Layer Caching:} Dependencies installed before code copy to leverage Docker's layer caching
    \item \textbf{Minimal Base Image:} \texttt{python:3.9-slim} reduces image size vs. full Python image
    \item \textbf{Cleanup:} APT cache removed to reduce layer size
    \item \textbf{.dockerignore:} Excludes venv/, \texttt{\_\_pycache\_\_/}, .git/ to prevent bloat
\end{itemize}

@app.route('/predict', methods=['POST'])
def predict():
    if 'image' not in request.files:
        return jsonify({'error': 'No image provided'}), 400
    
    # Load and preprocess image
    image = Image.open(request.files['image']).convert('L')
    image = transform(image).unsqueeze(0)
    
    # Model inference
    with torch.no_grad():
        output = model(image)
        prediction = output.argmax(dim=1).item()
        confidence = F.softmax(output, dim=1)[0][prediction].item()
    
    # Return JSON response
    return jsonify({
        'emotion': EMOTION_CLASSES[prediction],
        'confidence': float(confidence),
        'inference_time_ms': inference_time * 1000
    })
\end{lstlisting}

\section{Conclusion and Future Work}

\subsection{Project Summary}

This project successfully demonstrated the implementation of a complete facial expression recognition system using modern deep learning and MLOps practices. The key achievements include:

\begin{itemize}[itemsep=0.3em]
    \item Designed and trained a custom CNN achieving 61.77\% test accuracy on FER-2013
    \item Containerized the entire ML pipeline using Docker for reproducibility
    \item Deployed a production-ready REST API for real-time emotion inference
    \item Implemented best practices for model training, evaluation, and deployment
    \item Documented the complete workflow from data preprocessing to API deployment
\end{itemize}

The final model demonstrates strong performance on well-represented emotions (Happy: 86.4\% recall, Surprise: 74.9\%) while struggling with minority classes (Disgust: 17.1\% recall) due to class imbalance. Training on CPU-only hardware in 1.1 hours proved feasible for this dataset size, though GPU acceleration would significantly reduce training time.

\subsection{Lessons Learned}

\subsubsection{Technical Insights}

\begin{itemize}[itemsep=0.3em]
    \item \textbf{Class Imbalance Impact:} The 16.4× imbalance between Happy and Disgust classes severely affected minority class performance
    \item \textbf{CPU Training Viability:} Modern CPUs can train moderately-sized CNNs (2.46M params) in reasonable time (1.1 hours) for datasets of 35K images
    \item \textbf{Batch Size Trade-offs:} Smaller batch sizes (32 vs 64) improved generalization at the cost of training time
    \item \textbf{Regularization Effectiveness:} Combined dropout (25\% conv, 50\% FC) and weight decay (1e-4) prevented overfitting
\end{itemize}

\subsubsection{MLOps Best Practices}

\begin{itemize}[itemsep=0.3em]
    \item \textbf{Containerization Benefits:} Docker eliminated "works on my machine" issues and enabled seamless deployment
    \item \textbf{Volume Mounting:} Separating code, data, and model artifacts simplified workflow and enabled persistence
    \item \textbf{Reproducibility:} Fixed seeds + locked dependencies ensured identical results across runs
    \item \textbf{API Design:} RESTful API with JSON responses enabled easy integration with external applications
\end{itemize}

\subsection{Future Improvements}

\subsubsection{Model Enhancements}

\begin{enumerate}[itemsep=0.3em]
    \item \textbf{Class Imbalance Mitigation:}
    \begin{itemize}
        \item Implement focal loss to focus on hard-to-classify examples
        \item Use class-weighted loss functions
        \item Apply SMOTE or other synthetic oversampling techniques
    \end{itemize}
    
    \item \textbf{Architecture Improvements:}
    \begin{itemize}
        \item Experiment with ResNet, EfficientNet, or Vision Transformers
        \item Add attention mechanisms to focus on facial features
        \item Implement ensemble methods combining multiple models
    \end{itemize}
    
    \item \textbf{Training Optimizations:}
    \begin{itemize}
        \item Transfer learning from ImageNet-pretrained models
        \item Curriculum learning: start with easy examples, progress to hard ones
        \item Mixed precision training (if GPU available)
    \end{itemize}
\end{enumerate}

\subsubsection{Data Improvements}

\begin{enumerate}[itemsep=0.3em]
    \item \textbf{Data Augmentation:}
    \begin{itemize}
        \item Add Cutout, MixUp, or CutMix augmentations
        \item Implement AutoAugment for learned augmentation policies
    \end{itemize}
    
    \item \textbf{Dataset Expansion:}
    \begin{itemize}
        \item Supplement with RAF-DB, AffectNet, or EmotioNet datasets
        \item Collect additional samples for minority classes
        \item Apply active learning to identify hard examples
    \end{itemize}
\end{enumerate}

\subsubsection{Deployment Enhancements}

\begin{enumerate}[itemsep=0.3em]
    \item \textbf{Performance Optimization:}
    \begin{itemize}
        \item Model quantization (INT8) for faster inference
        \item ONNX conversion for cross-platform deployment
        \item TensorRT optimization for NVIDIA GPUs
    \end{itemize}
    
    \item \textbf{Production Features:}
    \begin{itemize}
        \item Kubernetes orchestration for scalability
        \item Load balancing for high-throughput scenarios
        \item Model monitoring and A/B testing infrastructure
        \item Automated retraining pipeline
    \end{itemize}
    
    \item \textbf{User Interface:}
    \begin{itemize}
        \item Web-based demo application
        \item Real-time webcam emotion detection
        \item Mobile app deployment (TensorFlow Lite)
    \end{itemize}
\end{enumerate}

\subsection{Broader Impact Considerations}

Facial expression recognition systems have significant societal implications:

\begin{itemize}[itemsep=0.3em]
    \item \textbf{Privacy Concerns:} Emotion detection can be intrusive; deployment should respect user consent
    \item \textbf{Bias and Fairness:} Models may perform differently across demographics; fairness audits are essential
    \item \textbf{Ethical Use Cases:} Prefer beneficial applications (healthcare, education) over surveillance
    \item \textbf{Cultural Sensitivity:} Emotion expression varies across cultures; models should be validated accordingly
\end{itemize}

\subsection{Final Remarks}

This project demonstrates that modern deep learning and containerization technologies make it feasible to build, train, and deploy emotion recognition systems on commodity hardware. The combination of PyTorch for model development, Docker for reproducibility, and Flask for API deployment provides a solid foundation for production ML systems.

The 61.77\% accuracy achieved represents a good baseline for further improvement through the techniques outlined above. Most importantly, the fully containerized and documented workflow ensures that this project serves as a reproducible template for future emotion recognition research and applications.
